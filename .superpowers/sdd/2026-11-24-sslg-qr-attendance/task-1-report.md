## Root-Cause Findings

### 1. Manila Date Fixture Is Internally Inconsistent

The test supplies `2026-11-23T15:30:00.000Z` and expects Manila date `2026-11-24`. Manila is UTC+8, so that instant is `2026-11-23T23:30:00+08:00`, still November 23. The implementation correctly returns:

- Date: `2026-11-23`
- Timestamp: `2026-11-23T23:30:00+08:00`

A direct `Intl.DateTimeFormat` check confirmed:

```text
2026-11-23T15:30:00.000Z => 2026-11-23, 23:30:00
2026-11-23T16:30:00.000Z => 2026-11-24, 00:30:00
```

Therefore the supplied fixture does not cross Manila midnight, despite the test name. Changing the production timezone or date logic to force the expected value would make the required `Asia/Manila` behavior incorrect.

### 2. CSV Header Expectation Conflicts with Supplied Implementation

The test expects:

```text
name,mode
"Ana","IN"
```

The supplied `toCsv_` builds `[headers, ...rows]` and applies `csvEscape_` to every cell. The supplied `csvEscape_` always surrounds values with quotes, so the actual and internally consistent output is:

```text
"name","mode"
"Ana","IN"
```

Quoted headers are valid CSV. Special-casing headers would require deviating from the exact implementation provided in the brief.

### Important (test suite — why QUALITY: CHANGES REQUESTED)
1. **No test guards "all reasons".** Fixture entities carry at most one `review_reasons` entry (`tools/tests/test_sslg_navigation.py:24,38,70`), so replacing `render_review_queue` with a version emitting only `review_reasons[:1]` passes **all 9 tests** (measured: `run=9 failures+errors=0`). Real data has 4 records and 4 activities with 2 reasons each; a truncation regression would ship silently. Fix: add a two-reason fixture and assert both bullets.
2. **No test guards Timeline row ordering.** Substituting an unsorted `render_timeline` passes all 9 tests (measured: `run=9 failures=0`) — `test_timeline_separates_record_dates_from_event_dates` (`:95-111`) checks membership/counts but never date monotonicity, while the brief requires "deterministic tables sorted by … event_date/date". Disk output is currently correctly sorted (verified); the suite just cannot catch it breaking. The Activity Dashboard ordering *is* genuinely tested (mutation of `_sorted_by_date` fails exactly `test_activity_dashboard_sorts_by_start_date_and_links_hubs`).
3. **Vacuous half of `test_home_exposes_all_reading_routes`.** `assertIn("Governance"/"External Memoranda", text)` (`:55-56`) matches the unconditional `###` headings emitted even for empty data (`tools/sslg_navigation.py:101-109`); deleting every collection member link passes all 9 tests (measured: `failures=0`). This is the "assertion that tests the test" the brief warned about. The four dashboard route bullets and the notice text *are* properly guarded (removing route bullets fails the test).
4. **Reason-based inclusion unguarded for records.** A status-only renderer (`r["status"] == "needs-review"` without the `or review_reasons` clause) passes all tests because `DATA` (`:32-45`) has no record that has reasons without needing-review status (the real corpus has 2, e.g. the `final`-status OM-SSLG-IA policy note now in the queue). The equivalent activity path *is* guarded via `act-b` (mutation fails `test_review_queue_lists_needs_review_activities_too`).
